## Принятые решения

| Вопрос | Решение |
|---|---|
| Подход | Постепенный редизайн волнами; слой данных (React Query + сервисы) сохраняется |
| Компонентная база | shadcn/ui + Radix поверх Tailwind v4 |
| Приоритет первой волны | Студент (тесты, психология, мобильная версия) |
| Языки | i18next: узбекский по умолчанию + русский, переключатель в навбаре |

## Почему редизайн нужен (диагноз текущего фронтенда)

- ~30 вызовов `alert()` вместо уведомлений; успех действий почти не подтверждается.
- Мобильной версии нет: все списки — десктопные таблицы с горизонтальным скроллом.
- Нет системы: заголовки, пустые состояния и загрузка на каждой странице сделаны по-своему; только 8 из 33 страниц показывают ошибку загрузки.
- Визуальные баги: двойная обёртка `hsl(var(--x))` делает часть цветов невидимой (в т.ч. цвет оценки в окне результата); классы `animate-in` мертвы — `tailwindcss-animate` не установлен.
- Бренд-цвет NDKTU `#242CBB` не является основным цветом темы (тема на другом индиго).
- Смесь языков: EduPlan-страница на русском, отдельные кнопки на английском, остальное на узбекском.
- Модалки без Esc/фокус-ловушки/блокировки прокрутки.
- Файлы страниц до 713 строк с 15–18 `useState`.
- Мёртвый код: `lib/tokens.ts` (не импортируется), legacy `tailwind.config.js`, дубль `cn()`, неиспользуемый `TableEmpty`.

## Что НЕ трогаем

- Слой данных: React Query-хуки, axios-сервисы, схемы Zod.
- Backend API и бизнес-логику.
- Логику проктаринга (WebSocket к face-detection) — меняем только её внешний вид.

## Риски

- **Проктаринг** — не ломать WebSocket-поток и логику предупреждений; менять только представление, проверять на реальной камере.
- **Продакшн-данные в локальной БД** — тестировать аккуратно, ничего не мутировать массово.
- **Смешанный стиль в переходный период** — неизбежен при волнах; порядок волн (сначала студент) минимизирует видимость для конечных пользователей.

Итого ориентировочно **9–10 недель** одним разработчиком; волны независимы — после каждой систему можно показывать и деплоить.
